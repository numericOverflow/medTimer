# Overview reminder groups, backdated resolution and the resolved section

The Overview shows the events of one day as reminder groups. A reminder group holds the reminder events that share one reminder timestamp, and it renders as one card under one time header. The group key is exact timestamp equality, through `groupBySameTime` in `:feature:reminders:api`. A tolerance window was considered and rejected. A merged notification records its anchor instant on every member, so exact equality keeps the Overview group, the notification and the recorded history in agreement. A window would split a merged notification across two cards and break the `reminderId to remindedTimestamp` dedup key in `OverviewViewModel.getFiltered`. Grouping follows `combine_notifications`, whose default is now on. With the setting off, every event forms its own group.

Each event stays its own lazy list item, and the first item of a group draws the group header. The rows of one group round only their outer corners, so the group reads as one card. A single lazy item per group was rejected because `OverviewRobot` scrolls by lazy item index and addresses rows through the running index of `OverviewTestTags.event`. The state button stays outside the card on the left, and the rail keeps drawing from the button centers. Inside a group, the rail shrinks its inset so that a short pill still links the rows.

Long-press selection mode stays beside the new header. The header adds `Confirm all` and an overflow menu. Both derive from `MultipleActions`, so the header never offers more than the selection bar offers for the same events. `Confirm all` marks only the unresolved events of a group taken, so a part-resolved group keeps the times that were already logged.

One choke point records the taken time. `NotificationProcessor.setReminderEventStatus` takes an optional processed time, and `ReminderCommandBus.markReminderEvents` forwards it. The `Taken at...` action supplies a picked time. Without a picked time, a dose marked taken records the time that `resolveTakenTime` picks from the default taken time setting. That function never returns a time after the current time, because interval and linked reminders derive their next due time from the recorded time. Every path that marks a dose taken passes through this point: the Overview, the notification buttons, the variable amount dialog and automatically taken reminders.

Fully resolved groups move into a collapsible `Resolved` section at the bottom of the day. A part-resolved group stays with the open groups, so that one time never splits across two cards. The section is collapsed by default, and the choice persists in `PersistentData`. The section opens on its own for a day without open groups and for a filter to taken or skipped doses. Its header rides on the first resolved item while the section is open, and it takes an item of its own only while the section is collapsed, behind every event. This keeps the lazy item index equal to the running event index. The test seam `overviewResolvedSectionEnabled` keeps the time order for the instrumented tests that act on a row index. The tests of the section switch it back on.
